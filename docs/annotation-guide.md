# 出行链标注规范 v0.1

该规范是尚未接入真实业务数据时的默认草案。正式标注前，应结合数据来源和业务口径评审并冻结版本。

## 标注对象

一条样本对应一段纯文本。`trip_chain` 按文本描述的实际出行顺序记录一个或多个行程段。每一段从一个出发地到一个目的地；换乘且交通方式改变时拆成新行程段。

## 字段规则

- `id`：样本唯一标识。
- `source_id`：原始记录标识。由同一记录切出的样本必须相同，用于防止数据泄漏。
- `person_id`：可选的匿名人员标识；未知时填 `null`。
- `text`：未经模型改写的原始文本。
- `sequence`：从 1 开始连续编号，不允许重复或跳号。
- `origin` / `destination`：优先保留文本中的最小完整地点表达；未提及时填 `null`。
- `departure_time` / `arrival_time`：完整可确定的日期时间写为 ISO 8601；只有时刻时写 `HH:MM`；相对或模糊时间保留原文短语，不得猜测日期。
- `transport_mode`：只能使用 Schema 中的枚举值。文本明确没有给出时填 `null`，明确表达但无法归类时填 `其他`，语义含混时填 `未知`。
- `purpose`：规则同交通方式。返回居住地统一标为 `回家`。

## 缺失与证据原则

缺失字段统一使用 JSON `null`，不得用空字符串、`无` 或臆测值代替。所有非空值都必须能在文本中找到直接证据或无歧义的规范化依据。

## 拆分规则

数据集按 `source_id` 分组拆分为训练、验证、测试集。同一 `person_id` 如果可获得，也应只出现在一个集合中。测试集在提示词、标签规范和模型参数定稿前锁定，不参与调参。
